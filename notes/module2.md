This is one of the most important things to understand because the two sound

PLAN → CAPTURE → MANAGE → ANALYZE → ARCHIVE → DESTROY

The data analysis process describes how an analyst uses data to solve a problem:

ASK → PREPARE → PROCESS → ANALYZE → SHARE → ACT

2. The Six Stages of the Data Life Cycle

1. Plan

Before collecting data, decide:

What data is needed?

How will it be managed?

Who is responsible for it?

What outcome do we want?

Example

An electricity company wants to help customers reduce electricity usage.

It might plan to collect:

Annual electricity usage

Type of building

Devices being used

It also decides who will collect, store, and share the information.

2. Capture

Capture = collect the data.

Data can come from many sources.

For example:

Public datasets

Company documents

Files

Databases

Surveys

A database is simply:

A collection of data stored in a computer system.

The course emphasizes that when collecting customer data, integrity, credibility,

and privacy are important.

3. Manage

Manage = take care of the data.

This includes:

Where data is stored

How it is stored

Keeping it secure

Maintaining it

Tools used to manage it

Cleaning/maintaining the data

Think:

Capture = get the data.

Manage = look after the data.

4. Analyze

This is where the data is actually used to:

Solve problems

Make decisions

Support business goals

Find useful information

This connects directly to what you learned in Module 1.

5. Archive

Archive = store data that may not currently be used but could be needed later.

Example:

A company has five years of old customer records.

It might not need them every day, but instead of deleting them, it archives them.

Think:

Archive = keep it, but put it away.

6. Destroy

Destroy = securely remove data when it is no longer needed.

This could involve:

Securely deleting digital files

Erasing hard drives

Shredding paper documents

Removing shared copies

This is especially important when dealing with private company or customer

information.

3. Data Life Cycles Can Be Different

There isn't one universal data life cycle that every organization must use.

Different organizations may organize the stages differently.

U.S. Fish and Wildlife Service

Plan → Acquire → Maintain → Access → Evaluate → Archive

U.S. Geological Survey

Plan → Acquire → Process → Analyze → Preserve → Publish/Share

It also performs activities throughout the cycle such as:

Documentation

Quality management

Backup

Security

Financial institutions

Capture → Qualify → Transform → Utilize → Report → Archive → Purge

Harvard Business School

Generation → Collection → Processing → Storage → Management → Analysis

→ Visualization → Interpretation

So don't memorize every organization's cycle for the exam unless your course

specifically asks you to.

What you SHOULD remember:

Data life cycles vary depending on the organization and its needs.

But the general principle stays the same:

Data must be governed so that it is accurate, secure, and available when

needed.

4. The ASK Phase

Now we move back to the data analysis process.

Remember:

ASK → PREPARE → PROCESS → ANALYZE → SHARE → ACT

The Ask phase has three major jobs:

1. Understand stakeholder expectations

2. Define the problem

3. Decide what questions need to be answered

What is a stakeholder?

A stakeholder is someone who:

Has invested time/resources into a project

Cares about the outcome

Can influence decisions or actions

Has specific goals they want achieved

Examples:

Manager

Executive

Sales team

Client

Project sponsor

Example

Your manager says:

"Analyze the company's business risks."

Don't immediately start downloading data.

First ask:

"Which risks are we interested in?"

Maybe they mean:

All business risks

OR

Only weather-related risks

That clarification is part of the Ask phase.

5. Defining the Problem

To define a problem, compare:

Current state vs Ideal state

Example:

Current state

Customers wait 20 minutes in a ticket line.

Ideal state

Customers should get into the arena much faster.

Problem

The ticketing process is causing excessive waiting time.

This is important because an analyst shouldn't simply treat the symptom.

You want to understand the actual problem.

That's where the Five Whys from Module 1 can help.

6. PREPARE Phase

The Prepare phase asks:

What data do we need to answer our questions?

You need to:

Identify useful data

Locate the data

Decide how to collect it

Store/access it responsibly

Consider whether the data is objective and unbiased

Data could be:

Quantitative — numerical data

Qualitative — descriptive/non-numerical information

Cross-sectional — data from a particular point in time

Longitudinal — data collected over a longer period

Important idea

Sometimes you need to collect new data.

Other times, the data already exists.

For example, an employee engagement project might use an existing company

survey rather than creating an entirely new dataset.

10. ACT Phase

This is the final step.

The organization actually uses the insights.

Formulas vs Functions

This is worth knowing.

Formula

A formula is a set of instructions that performs a calculation.

Examples:

=A1+B1

=A1*B1

You create the calculation yourself.

Function

A function is a pre-built command that performs a particular task.

Examples:

=SUM(A1:A10)

=AVERAGE(A1:A10)

Think:

Formula = instructions you construct.

Function = ready-made calculation.

13. Databases and SQL

Database

A collection of data stored in a computer system.

Query

A request for data or information from a database.

Query language

A programming language used to communicate with a database.

SQL

Structured Query Language

SQL allows analysts to communicate with databases.

For example:

SELECT name, age

FROM users;

You're basically telling the database:

"Give me the name and age from the users table."

SQL can be used to:

SELECT data

INSERT data

UPDATE data

DELETE data

This should feel familiar to you because you've already done basic SQL. The course

is essentially putting that knowledge into the data analyst workflow.
